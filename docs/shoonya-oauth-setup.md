# Shoonya OAuth credential setup

This application uses Shoonya OAuth, not the legacy QuickAuth login. Do not configure Vendor Code, IMEI, or TOTP auto-login for this OAuth flow.

## Prerequisites
- Shoonya API access enabled for your account.
- A static public IP address for the backend host, registered in Shoonya's API Key settings.
- Client ID and Secret Code from the API Key settings. Keep the Secret Code private.
- Registered redirect/callback URI matching the backend's `SHOONYA_REDIRECT_URI`.

## OAuth endpoints
- Authorize: `https://api.shoonya.com/OAuthlogin/authorize/oauth?client_id=<CLIENT_ID>`
- REST host: `https://api.shoonya.com/NorenWClientAPI/`
- WebSocket: `wss://api.shoonya.com/NorenWSAPI/`

## Login procedure
1. Register/confirm the backend's static IPv4 address under Shoonya API Key settings.
2. Configure `SHOONYA_REDIRECT_URI` in the backend environment to the exact registered HTTPS callback.
3. Obtain Client ID and Secret Code from the Shoonya API Key settings. Do not commit these values or paste them into chat.
4. Generate an OAuth authorization URL using the Client ID, sign in on Shoonya's hosted page, and capture the returned one-time authorization code.
5. Submit the one-time authorization code and Secret Code to the backend's authenticated OAuth verify endpoint. The backend computes SHA-256 of `client_id + secret_code + auth_code`, calls `GenAcsTok`, and verifies the returned UID/account ID against the requested identity. The current verify API accepts `client_id` and `secret_code` in its HTTPS request body; these are not yet read from dedicated backend environment settings.
6. Treat the access token as a secret. Shoonya access tokens expire after 24 hours and must be regenerated by a new OAuth flow; do not assume refresh-token renewal.

## Existing application behavior
- The OAuth flow correlation ID is single-use and expires after 10 minutes.
- OAuth exchange is protected by owner access and account identity checks.
- Broker connection remains kill-switch disabled for real trading after authentication.
- This guide does not enable market-data shadow feed or failover; those require separate explicit configuration and validation.

## Security
- Store secrets in a private backend deployment environment/secret store only.
- Never commit credentials, auth codes, access tokens, or checksums.
- Do not log credential values or OAuth token responses.
- Use a static IP; if the outbound IP changes, re-register it before attempting login.
